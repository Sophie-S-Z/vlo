# M1 Landing Page and Waitlist Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking. M1 has four parts (M1a to M1d). This file details M1a; each later part gets its task detail added here before it starts.

**Goal:** The `/` landing page from spec section 18 with every section, true copy, and a working waitlist, so sign-ups start during the build.

**Architecture:** The landing page stays prerendered HTML (ADR 0003 amendment). Every effect is progressive: the static page is complete and accessible, and effect code loads after hydration through dynamic `import()` only when `useMotionPreferences().reduced` is false. GSAP, Lenis and Motion live in lazy chunks, so the initial bundle and LCP do not grow. The waitlist talks to Supabase through two security definer RPCs over plain `fetch` in `src/net/`, with no Supabase client library.

**Tech Stack:** gsap 3.15 (+ ScrollTrigger, SplitText, ScrambleTextPlugin, DrawSVGPlugin, MorphSVGPlugin, Flip, Observer, CustomEase) with @gsap/react 2.1, lenis 1.3, motion 14, PostgreSQL 16 for SQL tests. M1b adds three 0.187, @react-three/fiber 9, drei 10, postprocessing. M1c and M1d add matter-js 0.20 and tweakpane 4.

**Spec:** `docs/BUILD_PROMPT.md` sections 18, 19, 20, 21, 22 (M1).

## Global Constraints

- Never show fake numbers, users or reviews. Describe features as "coming" or "built for". Show "N writers are waiting" only when N ≥ 100.
- All headline text is real HTML text. Use only copy from section 20, polished with `humanize-writing`, and keep every claim true to section 4.
- Every effect has a still fallback. Calm or reduced motion turns off Lenis, pinning, WebGL and sound; sections stack with still SVG art.
- LCP under 2.5 s with the HTML headline as the LCP element. Initial JS under 250 KB gzip. three, matter-js and tweakpane load lazily.
- 0 axe violations of serious or critical impact. Works at 360 px with no horizontal scroll.
- No third-party scripts. Every outgoing request goes through `src/net/` and its log. Add the Supabase host to `scripts/csp.ts` from `VITE_SUPABASE_URL` at build time.
- Waitlist client rules: reject the submit if the honeypot has text or the form was filled in under 2 seconds. Enter submits at once for keyboard users. Use `aria-live`.
- Motion tokens: CustomEase "vlo" = 0.65, 0, 0.35, 1; reveals 0.6 to 1.2 s; springs stiffness 300, damping 30.

## Review Focus

1. Supabase is down, paused (free plan pauses after 1 week) or the env vars are missing: the form shows a clear, honest error and keeps the typed email. Test in `waitlist/api.test.ts` and `WaitlistForm.test.tsx`.
2. Same email with different case or spaces (`A@B.com `): one row, same position (citext plus client trim). SQL test and API test.
3. HTTP 429 or a slow network: no retry loop; the button stays disabled while one request runs. API test.
4. Visitor turns Calm on mid-scroll: Lenis, ScrollTrigger pins and running tweens stop and the page stays readable with no stuck pin spacers. E2E test in `landing-motion.spec.ts`.
5. JavaScript off or effect chunk fails to load: every section, the FAQ (native `<details>`), and the waitlist form (with a clear "needs JavaScript" note on submit) still render. E2E with `javaScriptEnabled: false`.

## M1a

### Task 1: Waitlist database migration and SQL tests

**Files:** `supabase/migrations/20261030000000_waitlist.sql`, `supabase/tests/waitlist.test.sql`, `scripts/test-sql.sh`, CI job `sql`

- Migration: section 19 SQL, checked against current Supabase docs, plus `revoke all on table public.waitlist from anon, authenticated`, an explicit `grant execute ... to anon` only, and validation of `writer_type` before insert (raise `invalid_writer_type`).
- Tests run as role `anon` on a throwaway PostgreSQL 16 database (local `pg_ctl`; CI service container): direct select/insert on the table fails; `join_waitlist` returns place 1 then 2; same email in other case returns the same place and code (US17); invalid email raises `invalid_email`; pain point over 280 characters is cut to 280; `waitlist_count()` matches rows.

### Task 2: Network module and log

**Files:** `src/net/request.ts`, `src/net/log.ts`, tests beside them
**Produces:** `netRequest({ purpose: NetPurpose; url: string; init?: RequestInit }): Promise<Response>`; `type NetPurpose = "waitlist" | "waitlist-count"` (M4 extends it); `getNetLog(): readonly NetLogEntry[]` with `{ time, host, purpose, bytesSent, status }`; `subscribeNetLog(fn)`.

- Tests: each call adds one entry with host and byte size; a thrown network error still logs with status 0; no request body text is stored in the log.

### Task 3: Waitlist API client

**Files:** `src/landing/waitlist/api.ts`, `api.test.ts`, `src/landing/waitlist/config.ts`
**Produces:** `joinWaitlist(input: { email; writerType?; painPoint?; referredBy? }): Promise<{ place: number; refCode: string }>`; `getWaitlistCount(): Promise<number | null>`; `WaitlistError` with `code: "invalid_email" | "not_configured" | "rate_limited" | "unavailable"`; `validateSubmission({ honeypot, startedAt, now }): "ok" | "bot"`.

- POST `${VITE_SUPABASE_URL}/rest/v1/rpc/join_waitlist` with `apikey` and `Authorization: Bearer <anon key>` headers. Trim and lower-case the email. `referredBy` from `?ref=` (letters and digits, max 20).
- Tests (mocked `fetch`): request shape; 429 maps to `rate_limited` with no retry; network error maps to `unavailable`; missing env maps to `not_configured`; honeypot or under 2 s returns `bot`.

### Task 4: Landing content and structure (no effects)

**Files:** `src/landing/sections/*.tsx` (Entry, Hero, Manifesto, BookOpens, ThreeForms, Privacy, AiOnYourTerms, FeaturesBento, FirstLines, Faq, Waitlist, Footer), `src/landing/art/*.svg` still art, `src/landing/copy.ts`

- Each section is one landmark region with an `h2` (Hero keeps the `h1`). Copy comes from `copy.ts`, which holds section 20 text verbatim after the humanize pass. First lines list only the 12 public-domain lines.
- Tests: every section renders its heading; `copy.ts` first lines equal the section 20 list; no digit-based claim appears except `$0` and live data.

### Task 5: Waitlist form (M1a version)

**Files:** `src/landing/waitlist/WaitlistForm.tsx`, test beside it

- Email with floating label, "I write" segmented control (Novels, Memoir, Poetry, A bit of everything → `novels|memoir|poetry|mixed`), optional 280-character field with a counter, hidden honeypot, consent line (blocked text until the reply-to email arrives: show the line without the address). A plain submit button now; hold-to-sign replaces it in M1d, with Enter still submitting at once.
- Success shows "You're writer #N on the Vlo list." and "Copy your invite link" (`?ref=CODE`). Errors use `role="alert"`; status uses `aria-live="polite"`.
- Tests: success path; duplicate shows the same number; each `WaitlistError` code shows its message; the email stays after an error.

### Task 6: Global HTML-level effects (lazy)

**Files:** `src/motion/gsap.ts` (registers plugins and CustomEase "vlo"), `src/landing/effects/index.ts` (dynamic entry), `effects/lenis.ts`, `inkLine.ts`, `pageCounter.ts`, `nav.ts`, `cursor.ts`, `magnetic.ts`, `velocitySkew.ts`, `reveals.ts`, `scrollFill.ts`, `cursorWeight.ts`, `marquee.ts`, `tilt.ts`

## M1b: the particle field (detail)

ADR 0008 records the choice of plain three.js plus `postprocessing` for the landing canvas.

### Task 1: Shape samplers (pure, tested first)

**Files:** `src/gl/shapes/*.ts`, `src/gl/random.ts` (seeded RNG).
**Produces:** `sampleShapes(count, seed) => Float32Array[]`, seven arrays of `count * 3` positions in a unit space (x and y in -1..1, z in -0.5..0.5).

- Wordmark from text drawn on a 2D canvas (`OffscreenCanvas` or `document.createElement("canvas")`), word cloud, open book with fanned pages, three formations, padlock, paper plane, wordmark again.
- Tests: every shape has `count` finite points inside the bounds; the same seed gives the same points.

### Task 2: Stage and particles

**Files:** `src/gl/stage.ts`, `src/gl/glyphAtlas.ts`, `src/gl/particles.ts`, `src/gl/shaders/*.glsl.ts`, `src/landing/effects/field.ts`.

- One fixed full-screen canvas behind the HTML (`aria-hidden`, no pointer events). DPR cap 1.5. Pause when the tab is hidden. 12,000 glyphs on desktop, 3,000 on phones.
- Instanced quads; seven target attributes; per-particle delay; curl-noise offset in transit; camera follows the cursor a little.
- Scroll scrubs `uProgress` from 0 to 6 across the pages. Colors come from the theme tokens and update on a theme change.
- Bloom, vignette and chromatic aberration that follows scroll velocity.
- While the canvas runs, the still SVG art hides. No WebGL, a lost context, Calm or reduced motion: no canvas and the still art shows.
- Tests: unit test for the progress mapping; e2e that the canvas exists with full motion, is gone after Calm (with the still art back), and never loads with reduced motion; bundle check keeps three out of the initial chunks; Lighthouse budgets still pass.

### Task 3: ASCII footer pass and hero ink fluid

- Shape 7 drawn through an ASCII pass near the footer.
- Hero ink fluid: port of the MIT WebGL-Fluid-Simulation, desktop only, cursor driven.

## M1c detail

All of it lives in the lazy effects chunk, except React state that must also work in Calm (the novel layout toggle, the memoir alias buttons, the privacy mode switch). Matter.js loads in its own chunk from the poetry effect only. Every effect returns a full teardown and keeps React-owned nodes (`keepChildren`, `setText`, or effect-owned `data-text` with CSS `content: attr(data-text) / ""`).

### Task 1: Horizontal track (p.04)

**Files:** `src/landing/effects/track.ts`, `ThreeForms.tsx`, `landing-motion.spec.ts`

- On screens 1024 px and wider, the three panels sit in one row and the section pins while the row moves left (ScrollTrigger pin, `x` tween). Panel effects use `containerAnimation`. Phones and Calm keep the vertical stack (18.1 item 11).
- E2E: at 1280 px the track moves left while the section stays pinned; Calm removes the pin spacer; at 360 px no horizontal scroll.

### Task 2: Novel panel

**Files:** `src/landing/effects/forms.ts`, `ThreeForms.tsx`, tests

- Grid/Board toggle is a React button (`aria-pressed`); the layout is CSS on `data-layout`. The effect animates the change with Flip (state read in a capture-phase click, `Flip.from` from a MutationObserver).
- In Board layout, cards drag with Draggable and InertiaPlugin; SVG threads join the cards in story order and redraw on drag (DrawSVG on reveal).
- Tests: unit (toggle works without effects); e2e (toggle changes layout; dragging a card moves its thread end).

### Task 3: Memoir panel

- Names are React buttons (`aria-pressed`) that swap between real name and alias on click or tap. The effect scrambles the visible text on hover and on change through `data-text`. Pure `scrambleText(from, to, progress, random)` is unit-tested.
- The life-stage line draws itself and the stages stagger in as the panel enters.

### Task 4: Poetry panel

- The poem types itself one character at a time (`setText` on the visible copy; the full poem is in an sr-only copy) with exact indents. Syllable counts sit in a right gutter (`DEMO_POEM_SYLLABLES`, counted by hand).
- Magnetic poetry: 30 word tiles. Without effects they wrap as a static list. With effects, Matter.js (lazy chunk) drops them into a box; visitors drag and throw them; scroll velocity tilts gravity a little. The physics pause when the box is off screen.
- E2E: matter-js chunk loads only after the panel nears view and never with reduced motion; tiles move under physics.

### Task 5: Privacy (p.05)

- Spring switch: a radio group for Pen, Reader and Co-writer with a sliding marker and a badge that morphs (MorphSVG) and shows the mode summary. It works in Calm without motion.
- Odometer: "Requests to Vlo: 0". The digits roll down to 0 when the section enters; every mode keeps 0, which is true (principle 2).
- Flashlight: the hidden line shows through a radial mask. The radius grows with scroll and reaches full reveal at the section's middle; a fine pointer moves the light. The text is always in the DOM and fully visible without effects.

### Task 6: First lines (p.08)

- With effects, the list becomes a draggable, wrapping grid with inertia (Draggable on a proxy, `gsap.utils.wrap`). Focus moving to a card's link pans the grid to it. Without effects, the static grid stays.
- Blank cards: click zooms a clone from the card to full screen, then glides to the waitlist and focuses the email field. Reduced motion: plain anchor jump.
- Marquees: speed follows scroll velocity; hover slows them.
- E2E: drag moves the grid and it wraps; the blank card leads to the waitlist with focus in the email field.

### Gate for M1c

Unit, e2e and axe pass on all projects; bundle guardrail passes with matter-js blocked from the initial chunk; Lighthouse LCP under 2.5 s, accessibility 1.0; code review done.

## M1d detail

### Task 1: Sound (spec 18.1 item 10)

**Files:** `src/audio/engine.ts` (lazy), `src/audio/SoundSwitch.tsx`, `SiteControls.tsx`, `Footer.tsx`, tests

- Off by default on every visit. The switch (`role="switch"`, "Sound") creates the AudioContext only on the visitor's click. Room tone: filtered noise at very low gain. UI ticks: a 30 ms sine blip on hover of links and buttons (fine pointers). Paper sound: a short band-passed noise burst on a successful sign-up.
- The switch shows four bars driven by an AnalyserNode; the film grain follows the level a little. Calm and reduced motion turn sound off and hide the bars' motion.
- Tests: unit (switch state, Calm forces off, engine called lazily); e2e (no AudioContext before a click).

### Task 2: Entry sequence (p.00)

**Files:** `src/landing/Entry.tsx`, inline head script in `index.html`, `src/landing/effects/entry.ts`, ADR 0009

- First visit with JavaScript and full motion only: the head script sets `html[data-entry]` before the first paint. The logo draws itself, a percentage follows real progress (fonts, effects chunk), three lines appear, then "Enter with sound" and "Enter in silence". The curtain splits from the center. A skip link is always visible; Escape skips. Repeat visits skip the lines.
- No JavaScript, reduced motion, Calm or a repeat visit: no curtain.
- Tests: e2e first visit shows the curtain and both buttons; "Enter in silence" removes it and focuses the main content; a repeat visit shows no lines; reduced motion shows no curtain. Lighthouse LCP stays under 2.5 s.

### Task 3: Sign-up flight and ticket (p.10)

- On success the form folds like origami into a paper plane (clip-path folds), the plane flies off on a MotionPath curve, the ticket card slides in with a drawn check. Errors shake gently. Reduced motion: the ticket shows at once.

### Task 4: Route wipes and 404 physics

- `/privacy` and `/ai-policy`: five vermilion bars wipe across on navigation, with the View Transitions API where supported. The 404 page drops the letters of "This page isn't written yet" under Matter.js; visitors drag and throw them. The heading stays real text.

### Task 5: Ink lab, gyroscope, frame-rate guard

- "~" opens a lazy Tweakpane panel (particle count, ink color, grain, bloom). The footer has an "Ink lab" button for the same panel.
- Phones: an "Enable motion" button asks for device-orientation permission, then the field and still art follow the tilt a little.
- Frame-rate guard (18.4): under 40 fps for 2 s halves the particles and stops the fluid; the existing guard still removes the field below about 22 fps.

### Task 6: Polish carried from M1a and M1c

- Cursor-driven Fraunces weight on Manifesto key words, magnetic fill from the entry point, copy-link check bounce tile, footer per-letter hover wave.
- TBT: split the effects chunk so each section loads its own code.
