# M1 Landing Page and Waitlist Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking. M1 has four parts (M1a to M1d). This file details M1a; each later part gets its task detail added here before it starts.

**Goal:** The `/` landing page from spec section 18 with every section, true copy, and a working waitlist, so sign-ups start during the build.

**Architecture:** The landing page stays prerendered HTML (ADR 0003 amendment). Every effect is progressive: the static page is complete and accessible, and effect code loads after hydration through dynamic `import()` only when `useMotionPreferences().reduced` is false. GSAP, Lenis and Motion live in lazy chunks, so the initial bundle and LCP do not grow. The waitlist talks to Supabase through two security definer RPCs over plain `fetch` in `src/net/`, with no Supabase client library.

**Tech Stack:** gsap 3.15 (+ ScrollTrigger, SplitText, ScrambleTextPlugin, DrawSVGPlugin, MorphSVGPlugin, Flip, Observer, CustomEase) with @gsap/react 2.1, lenis 1.3, motion 14, PostgreSQL 16 for SQL tests. M1b adds three 0.187, @react-three/fiber 9, drei 10, postprocessing. M1c and M1d add matter-js 0.20 and tweakpane 4.

**Spec:** `docs/BUILD_PROMPT.md` sections 18, 19, 20, 21, 22 (M1).

## Global Constraints

- Never show fake numbers, users or reviews. Describe features as "coming" or "built for". Show "N writers are waiting" only when N ≥ 100.
- All headline text is real HTML text. Use only copy from section 20, polished with `humanize-writing`, and keep every claim true to section 4.
- Every effect has a still fallback. Calm or reduced motion turns off Lenis, pinning, WebGL and sound; sections stack with still SVG art.
- LCP under 2.5 s with the HTML headline as the LCP element. Initial JS under 250 KB gzip. three, matter-js and tweakpane load lazily.
- 0 axe violations of serious or critical impact. Works at 360 px with no horizontal scroll.
- No third-party scripts. Every outgoing request goes through `src/net/` and its log. Add the Supabase host to `scripts/csp.ts` from `VITE_SUPABASE_URL` at build time.
- Waitlist client rules: reject the submit if the honeypot has text or the form was filled in under 2 seconds. Enter submits at once for keyboard users. Use `aria-live`.
- Motion tokens: CustomEase "vlo" = 0.65, 0, 0.35, 1; reveals 0.6 to 1.2 s; springs stiffness 300, damping 30.

## Review Focus

1. Supabase is down, paused (free plan pauses after 1 week) or the env vars are missing: the form shows a clear, honest error and keeps the typed email. Test in `waitlist/api.test.ts` and `WaitlistForm.test.tsx`.
2. Same email with different case or spaces (`A@B.com `): one row, same position (citext plus client trim). SQL test and API test.
3. HTTP 429 or a slow network: no retry loop; the button stays disabled while one request runs. API test.
4. Visitor turns Calm on mid-scroll: Lenis, ScrollTrigger pins and running tweens stop and the page stays readable with no stuck pin spacers. E2E test in `landing-motion.spec.ts`.
5. JavaScript off or effect chunk fails to load: every section, the FAQ (native `<details>`), and the waitlist form (with a clear "needs JavaScript" note on submit) still render. E2E with `javaScriptEnabled: false`.

## M1a

### Task 1: Waitlist database migration and SQL tests

**Files:** `supabase/migrations/20261030000000_waitlist.sql`, `supabase/tests/waitlist.test.sql`, `scripts/test-sql.sh`, CI job `sql`

- Migration: section 19 SQL, checked against current Supabase docs, plus `revoke all on table public.waitlist from anon, authenticated`, an explicit `grant execute ... to anon` only, and validation of `writer_type` before insert (raise `invalid_writer_type`).
- Tests run as role `anon` on a throwaway PostgreSQL 16 database (local `pg_ctl`; CI service container): direct select/insert on the table fails; `join_waitlist` returns place 1 then 2; same email in other case returns the same place and code (US17); invalid email raises `invalid_email`; pain point over 280 characters is cut to 280; `waitlist_count()` matches rows.

### Task 2: Network module and log

**Files:** `src/net/request.ts`, `src/net/log.ts`, tests beside them
**Produces:** `netRequest({ purpose: NetPurpose; url: string; init?: RequestInit }): Promise<Response>`; `type NetPurpose = "waitlist" | "waitlist-count"` (M4 extends it); `getNetLog(): readonly NetLogEntry[]` with `{ time, host, purpose, bytesSent, status }`; `subscribeNetLog(fn)`.

- Tests: each call adds one entry with host and byte size; a thrown network error still logs with status 0; no request body text is stored in the log.

### Task 3: Waitlist API client

**Files:** `src/landing/waitlist/api.ts`, `api.test.ts`, `src/landing/waitlist/config.ts`
**Produces:** `joinWaitlist(input: { email; writerType?; painPoint?; referredBy? }): Promise<{ place: number; refCode: string }>`; `getWaitlistCount(): Promise<number | null>`; `WaitlistError` with `code: "invalid_email" | "not_configured" | "rate_limited" | "unavailable"`; `validateSubmission({ honeypot, startedAt, now }): "ok" | "bot"`.

- POST `${VITE_SUPABASE_URL}/rest/v1/rpc/join_waitlist` with `apikey` and `Authorization: Bearer <anon key>` headers. Trim and lower-case the email. `referredBy` from `?ref=` (letters and digits, max 20).
- Tests (mocked `fetch`): request shape; 429 maps to `rate_limited` with no retry; network error maps to `unavailable`; missing env maps to `not_configured`; honeypot or under 2 s returns `bot`.

### Task 4: Landing content and structure (no effects)

**Files:** `src/landing/sections/*.tsx` (Entry, Hero, Manifesto, BookOpens, ThreeForms, Privacy, AiOnYourTerms, FeaturesBento, FirstLines, Faq, Waitlist, Footer), `src/landing/art/*.svg` still art, `src/landing/copy.ts`

- Each section is one landmark region with an `h2` (Hero keeps the `h1`). Copy comes from `copy.ts`, which holds section 20 text verbatim after the humanize pass. First lines list only the 12 public-domain lines.
- Tests: every section renders its heading; `copy.ts` first lines equal the section 20 list; no digit-based claim appears except `$0` and live data.

### Task 5: Waitlist form (M1a version)

**Files:** `src/landing/waitlist/WaitlistForm.tsx`, test beside it

- Email with floating label, "I write" segmented control (Novels, Memoir, Poetry, A bit of everything → `novels|memoir|poetry|mixed`), optional 280-character field with a counter, hidden honeypot, consent line (blocked text until the reply-to email arrives: show the line without the address). A plain submit button now; hold-to-sign replaces it in M1d, with Enter still submitting at once.
- Success shows "You're writer #N on the Vlo list." and "Copy your invite link" (`?ref=CODE`). Errors use `role="alert"`; status uses `aria-live="polite"`.
- Tests: success path; duplicate shows the same number; each `WaitlistError` code shows its message; the email stays after an error.

### Task 6: Global HTML-level effects (lazy)

**Files:** `src/motion/gsap.ts` (registers plugins and CustomEase "vlo"), `src/landing/effects/index.ts` (dynamic entry), `effects/lenis.ts`, `inkLine.ts`, `pageCounter.ts`, `nav.ts`, `cursor.ts`, `magnetic.ts`, `velocitySkew.ts`, `reveals.ts`, `scrollFill.ts`, `cursorWeight.ts`, `marquee.ts`, `tilt.ts`
**Produces:** `startLandingEffects(root: HTMLElement): () => void` (returns a full teardown).

- Load with `import()` after hydration only when not reduced; call the teardown when `reduced` turns true.
- Tests: unit test that teardown kills every ScrollTrigger and Lenis instance; e2e that Calm mid-page removes pin spacers and stops Lenis; bundle check that `gsap`, `lenis` and `motion` are not in the initial chunks (add them to `FORBIDDEN_IN_INITIAL`).

### Task 7: Section demos

**Files:** under `src/landing/demos/`: FAQ accordion (native `<details>` plus height animation), bento demos (snapshot slider, format labels, save check, timer ring, theme flip, mosaic, copy-link check, count to `$0`), AI cards with tilt, glare and card-to-modal (Motion `layoutId`), vanishing-point line in Manifesto.

- Tests: FAQ works by keyboard; modal traps focus and closes on Escape; reduced motion shows final states.
